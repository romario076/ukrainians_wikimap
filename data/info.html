🌍 Наші Люди Всюди

Першопочатково ідея проєкту полягала в тому, щоб відобразити на мапі світу місця народження українців, які мають статтю на Вікіпедії. Тоді за основу аналізу було взято 28 000 статей з Вікіпедії.

Тепер же, оновлена версія карти відображає інформацію, зокрема не тільки місця народження, але і місця смерті, про більше ніж 60 000 особистостей, які таким чи іншим чином пов'язані з Україною чи її історичними формуваннями, наприклад УНР чи Гетьманщина.

📌 За допомогою карт можна переглядати будь-які місця світу, можна зумити і наводити курсором на кожну точку, де буде виводитись додаткова інформація про кожну особу: ім'я, місце народження, дата народження, координати. Також, якщо клікнути — можна перейти на відповідну сторінку в Вікіпедії для більш детального ознайомлення.

📌 Використовуйте поле 🔍Пошук за іменем та прізвищем для фільтрації карти за ім’ям або прізвищем. Зверніть увагу: у Вікіпедії немає єдиного стандарту щодо порядку імені та прізвища — спочатку може йти як ім’я, так і прізвище. Тому, якщо ви шукаєте конкретну особу, спробуйте різні варіанти написання. Наприклад, якщо ви введете “Ющенко Віктор”, результатів не буде, оскільки у Вікіпедії третій Президент України вказаний як “Віктор Ющенко” — спочатку ім’я, потім прізвище. В інших випадках порядок може бути іншим. Якщо поле пошуку буде порожнім, карта автоматично повернеться до показу всіх даних. Зручно використовувати ключові частини імен, прізвищ для фільтрації даних на карті.

📌 Також додана інтерактивна статистика, що наглядно демонструє, як ті чи інші страшні події впливали на нашу популяцію та розселення українців.

🧠 Еволюція збору даних: Класичний метод (Ручне дослідження)

Для перших версій проєкту та для індивідуального точкового пошуку використовувався (і може успішно використовуватись вами зараз) класичний метод — прямий інструмент SPARQL-запитів до WikiData. Ви можете застосовувати цей сервіс для самостійного вивчення відкритих даних та маніпуляції з ними вручну.

Цей SPARQL-запит отримує інформацію про осіб, які пов’язані з Україною (як сучасною державою, так і її історичними формуваннями), та мають сторінку у українській Вікіпедії. Результатом роботи запиту є дані про місце народження, їх координати, дату народження, якщо відомо: місце смерті, їх координати, стать та інше.

Сервіс запитів Вікіданих (Wikidata Query Service): https://query.wikidata.org

Вікідані (Wikidata): Це велика безкоштовна, спільна, багатомовна база знань, яка збирає структуровані дані для підтримки Вікіпедії та інших проєктів Фонду Вікімедіа. У Вікіданих зберігаються факти про мільйони об'єктів та їхні взаємозв'язки.

🔍 Приклад класичного запиту:

SELECT ?person ?personLabel ?birthplaceLabel ?birthDate ?deathDate
	?deathplaceLabel ?wikipedia_url ?genderLabel ?affiliationLabel
	WHERE {
	  ?person wdt:P31 wd:Q5.                          
	  VALUES ?affiliation {
		wd:Q212                #Ukraine
	  }

	  ?person wdt:P27 ?affiliation.       
	  ?person wdt:P19 ?birthplace.
	  ?person wdt:P569 ?birthDate.
	  
	  OPTIONAL { ?person wdt:P570 ?deathDate. }
	  OPTIONAL { ?person wdt:P20 ?deathplace. } 

	  OPTIONAL { ?person wdt:P21 ?gender. }
      OPTIONAL { ?wikipedia schema:about ?person;
               schema:isPartOf .}
	  SERVICE wikibase:label { bd:serviceParam wikibase:language "uk". }
	}
LIMIT 10

🚀 Data Extractor: Нова ера автоматизованого збору даних

Хоча класичні SPARQL-запити чудово підходять для ручних досліджень, глобальне масштабування проєкту вимагало радикально іншого підходу. Великі запити часто стикалися з тайм-аутами серверів Wikidata або пропускали постатей через брак тегів у базі даних.

Тому в новій версії було впроваджено Data Extractor — інтелектуальний високопродуктивний конвеєр, що поєднує потужність семантичного аналізу, асинхронних технологій та геопросторової математики.

📢 Відкритий код: Оскільки наш проєкт побудований на принципах Open Source, архітектура інструменту є повністю відкритою! Кожен розробник або дослідник даних може самостійно розгорнути та запустити Data Extractor для власних аналітичних цілей, знайшовши його у нашому офіційному GitHub-репозиторії.

🛠 Чому це справжній технологічний прорив?

  • Гібридне виявлення (Multi-path Discovery): Замість лінійного пошуку система використовує 7 незалежних паралельних шляхів розвідки. Постаті ідентифікуються не лише за громадянством, а й за складними ознаками: місцем народження предків, мовними характеристиками та перехресними категоріями у світових архівах Вікіпедії.
  • Асинхронне ядро на максимальних швидкостях: Завдяки технологічному стеку httpx + asyncio, скрипт обробляє тисячі запитів одночасно. Розумна архітектура семафорів і динамічне балансування навантаження дозволяють викачувати гігабайти інформації миттєво, повністю уникаючи блокувань з боку API.
  • Геометрія замість слів (Ray-casting алгоритм): Якщо в текстовому профілі особи прямо не вказано країну, Data Extractor задіює геопросторову математику. Алгоритм Ray-casting аналізує координати народження і зіставляє їх із масивом складних математичних полігонів історичних кордонів України. Якщо точка всередині — система автоматично зараховує особу до датасету.
  • Семантичний ШІ-фільтр у реальному часі: Інструмент сканує вступні тексти статей, миттєво відсіюючи інформаційне сміття та залишаючи в базі лише тих діячів, які дійсно мають вагоме значення для глобальної карти.

🌟 Переваги нової архітектури для користувачів:

  • Абсолютна надійність: Завдяки модульній системі чекпойнтів (checkpointing), процес збору даних повністю захищений від збоїв мережі — його можна зупинити та відновити у будь-які момент без втрати прогресу.
  • Максимальна глибина карти: Тепер ми бачимо тих, кого "ігнорують" стандартні пошукові алгоритми — від напівзабутих героїв доби Середньовіччя до сучасних науковців української діаспори в Америці чи Австралії.
  • Бездоганна чистота результатів: Багаторівнева автоматична верифікація гарантує відсутність дублікатів та випадкових людей на вашому екрані.

Data Extractor — це ядро Ukrainians Wikimap, яке щодня трансформує хаотичний океан даних Вікіпедії у структурований літопис української нації. 🇺🇦✨

👥 Як обираються особи: Логіка семантичних маркерів

Нижче наведено концептуальний та стислий перелік ключових критеріїв, на основі яких алгоритм ідентифікує історичних постатей. Повна математична логіка відбору, багаторівневі умови фільтрації, а також вичерпні списки унікальних системних ідентифікаторів Wikidata містяться безпосередньо у коді нашого репозиторію.

  • Тип: особа (wdt:P31 wd:Q5 – "instance of human"). Тобто, вибираються статті лише про людей.
  • Зв'язок через державні утворення: Визначає приналежність особи до сучасної України чи її історичних попередників через громадянство, підданство чи офіційне визнання (код wdt:P27).
  • Етнічні маркери та субпопуляції: Завдяки новій логіці алгоритму, система вміє розпізнавати осіб за їхнім корінним походженням, належністю до унікальних етнографічних груп або важливих національних спільнот, що століттями розвивалися на теренах України (код wdt:P172).
  • Глобальна діаспора та мовний простір: У датасет автоматично залучаються представники численних хвиль української еміграції, а також особи, для яких рідною або основною мовою діяльності зафіксована українська (коди wdt:P103 / wdt:P1412).
  • Обов’язкові умови: Наявність активної сторінки в українській Вікіпедії, чітко верифікована дата народження та наявність географічних координат місця народження для коректної побудови інтерактивних точок на мапі.

❓ FAQ

Чому стаття про певну людину не потрапила в аналіз?

  • Її немає в українській Вікіпедії або її опис занадто короткий для семантичного ШІ-сита.
  • Не виконується одна з обов'язкових технічних умов автоматичного відбору (не вказано точні координати або відсутній верифікований лінк між Wikidata та Wikipedia).
  • Стаття містить критичні помилки розмітки, через що автоматичний багатопотоковий парсер відфільтрував її як пошкоджену для забезпечення чистоти фінальної мапи.

Чому точки опиняються на річці, озері чи далеко від центру міста?

  • Кожне місто або село має одну офіційну координату. Якщо для цього населеного пункту знайдено 100 осіб, усі позначки наклалися б одна на одну. Щоб цього уникнути, до координат додається штучний статистичний шум: позначки «розпорошуються» навколо офіційної точки, тож кожного видатного українця видно окремо.

📊 Кластеризація та AI-аналіз (Демо-версія)

У цьому розділі реалізовано інтелектуальний аналіз та автоматичне групування (кластеризацію) видатних постатей на основі текстового опису їхньої діяльності в отриманому датасеті. Це дозволяє виявити приховані зв'язки та сформувати семантичні спільноти людей за сферами їхнього впливу, професіями чи історичним контекстом.

⚙️ Як це працює з технічної точки зору:

  • Фільтрація та якість даних: Для побудови точної моделі аналізу було відібрано лише тих осіб, для яких вдалося отримати якісний та змістовний опис обсягом понад 30 символів.
  • Ембедінг (Текст як вектори): За допомогою сучасної мовної ШІ-моделі intfloat/multilingual-e5-small кожен текстовий опис трансформується у високорозмірний математичний вектор із 384 вимірами. Ця числова репрезентація кодує глибокий семантичний зміст тексту.
  • Стиснення простору (UMAP): Оскільки людський мозок фізіологічно не здатний сприймати простір, який має більше 3-х вимірів, ми застосовуємо складні топологічні алгоритми зниження розмірності UMAP. Вони акуратно згортають 384-вимірний простір смислів у зрозумілу для людини 2-вимірну площину, зберігаючи при цьому глобальні та локальні зв'язки між об'єктами.
  • Пошук закономірностей (HDBSCAN): Фінальний етап побудови карт знань покладено на алгоритм щільнісної кластеризації HDBSCAN. Він автоматично розпізнає згущення векторів на площині, ідентифікує межі кластерів та виділяє схожі групи людей в окремі тематичні блоки, відсіюючи випадковий інформаційний шум.

⚠️ Примітка: Наразі функціонал працює в режимі демо-версії, оскільки використовує безплатну полегшену ембедінг-модель. Попри це, вона демонструє дивовижну точність та відкриває абсолютно новий погляд на структурування української історичної спадщини.
